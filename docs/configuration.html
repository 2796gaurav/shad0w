Configuration & tuning#

shad0w works with no configuration at all. Everything below is optional. Each setting can be given four ways, and the first one found wins:

  1. Code or a CLI flag: shad0w.decision(..., alpha=0.02), Shadow(..., canary=0.1), shad0w proxy --alpha 0.02.
  2. An environment variable: SHAD0W_ plus the name in capitals, for example SHAD0W_ALPHA=0.02 or SHAD0W_NEVER_SERVE=fraud,self_harm.
  3. A config file: ./shad0w.toml, or the path in SHAD0W_CONFIG. A [questions.<name>] section overrides the top level for that one question.
  4. The defaults in the table below.
# shad0w.toml
alpha = 0.05
audit_rate = 0.02
mode = "shadow"            # watch first, then "serve"

[questions.fraud_check]
alpha = 0.01               # stricter for a costly decision
never_serve = ["fraud"]    # this label always goes to your LLM

See every effective value and where it came from:

shad0w config                    # every setting and its source
shad0w config --question intent  # with [questions.intent] applied
shad0w config --init             # write a commented shad0w.toml

Python reads the same values: shad0w.settings("intent") returns the resolved Settings.

The guarantee#

Setting Default What it does
alpha 0.05 The most the table may disagree with your LLM on the answers it serves. Lower is safer and serves less.
delta 0.1 The chance that the certificate itself is wrong because the calibration sample was unlucky. 0.1 means 90% confidence.
min_rows 1000 Logged LLM answers needed before train() runs. More rows usually certify a larger share. The hard minimum is 100.
cal_fraction 0.3 Share of the log held back to certify the table. Those rows are never trained on.
max_cal 3000 Upper limit on that calibration slice.

Picking α. 5% suits routing and triage, where a wrong answer costs a retry. Use 1–2% where a wrong answer is expensive. A lower α moves the threshold up, so the table serves fewer answers. Try several on your own log with shad0w train --alpha 0.02 before deciding: the printed certified share is what you would get.

Why there is no per-label α. The certificate controls one number: the disagreement rate over everything the table serves. A separate bound per label needs a different, per-class procedure and many more calibration rows for rare labels. For a label that must be stricter, use never_serve (always ask the LLM) or a per-question section with a lower alpha.

Rolling out#

Setting Default What it does
mode "serve" serve answers from the table when certified. shadow computes the table's answer but always returns your LLM's, and counts would_serve and shadow_disagreements. off skips the table.
canary 1.0 Share of certified answers the table may actually serve. 0.1 serves one in ten; the rest go to your LLM and are logged as usual.
never_serve [] Labels that always go to your LLM, even when the table is certain.
min_confidence none A confidence floor on top of the certificate. It can only make serving stricter: answers below it are deferred with the flag min_confidence.
force_threshold none Serve from the table above this confidence even when the certificate says no. This voids the guarantee for those answers: they carry certified=False and the flag manual_threshold, and shad0w logs a warning at start-up. Use it only to experiment.

min_confidence and force_threshold are deliberately asymmetric. Raising the bar keeps the certificate valid, because the table then serves a subset of what was certified. Lowering it does not, so shad0w marks every such answer as uncertified instead of pretending otherwise.

The rollout guide walks through shadow, then a canary, then serve.

Retraining and spot checks#

Setting Default What it does
audit_rate 0.01 Share of all decisions also sent to your LLM. Served answers are re-asked in the background; deferred ones are simply marked. The result is a uniform sample of live traffic, used for the live agreement figure and for honest re-certification.
auto_train 0 (off) Retrain in the background every N new logged answers.
retrain "gated" gated keeps the current table unless the new one certifies at least 80% of the old certified share. always swaps whatever comes out.
drift_window 500 Decisions in the drift guard's sliding window.
drift_margin 0.03 Rise in estimated error (absolute) that raises the drift flag and sends answers to your LLM until it clears.

Why the spot-check sample matters: once a table is serving, the log mostly holds the hard cases it deferred. Certifying a new table on those alone would describe a harder mix than your real traffic. When at least 100 spot-check rows exist, train() certifies on them instead, and the certificate records "calibration": "uniform-audit". With fewer, it falls back to a random held-out split and records "held-out-split". During the first weeks, audit_rate = 0.05 fills that sample faster.

Everything else#

Setting Default What it does
exposed false Treat inputs as adversarial: also defer answers that a few character edits could flip.
folder "shad0w" Where logs and bundles live: <folder>/<question>/log.jsonl and <folder>/<question>/bundle/.
trace none A JSON Lines file that receives every decision, table and LLM.
cost_per_call none What one LLM call costs you. The dashboard then shows money saved.
llm_latency_ms none LLM latency to assume until one is measured, so the dashboard shows time saved from the first table answer.
capture header, model, tools, decisions Proxy only: which request shapes count as decisions. Add json_schema to also capture any request with a named JSON schema. See the proxy page.
timeout 120 Proxy only: upstream timeout in seconds.

Other environment variables#

Variable What it does
SHAD0W_CONFIG Path of the config file, instead of ./shad0w.toml.
SHAD0W_LOG info or debug for log lines; debug prints one line per decision.
SHAD0W_OTEL 1 to emit OpenTelemetry spans.
SHAD0W_BASE_URL Default base_url for LLM teachers.
SHAD0W_NATIVE_LIB Path to a C core library to load instead of the bundled one.

Reading shad0w.toml needs Python 3.11, or pip install tomli on 3.10.
