How it compares#

Every learned method below was trained on the same logged LLM answers, split the same way, and certified with the same Learn-then-Test procedure at the same α and δ, so "answered without the LLM at α = 5%" is compared like for like. Decision models are a different kind of thing: a model you call instead of your LLM for every request, with calibrated probabilities but no bound against anything. They can also be shad0w's teacher.

What each row means#

  • shad0w table: hashed word/character table with 8-bit weights, trained on your LLM's logged answers, certified; answers in microseconds on a CPU.
  • semantic cache: embed the text (bge-small), return the logged answer of the nearest logged text when the cosine similarity clears a threshold. This is what vCache (Berkeley, ICLR 2026) does with a learned per-entry threshold; we apply the same certifier to the similarity so the comparison is fair. Needs an embedding model call per request.
  • embedding kNN router: like the cache, but a weighted vote over the 10 nearest logged texts.
  • small fine-tuned head: logistic regression on bge-small embeddings, the cheapest "fine-tune a small model" stand-in. Needs the embedding model at serving time.
  • exact-match cache: free, but only repeats.
  • decision models: OpenAI Decisions API (gpt-6-luna, $0.10 per 1M input tokens, output free), TypeSafe Jev (hosted), Kev (Apache-2.0, 0.8B–27B) and Laya (Apache-2.0, 421M). They answer typed questions directly in 10 ms–1 s. shad0w can learn from any of them and answer the certified share in microseconds. The open ones now run locally too: llama.cpp serves /v1/systemone (llama-server -hf ggml-org/Kev-0.8B-GGUF; also Laya, Julia-1, Clef-Flash and Nimble GGUFs) and Ollama 0.40 ships laya, so llm="systemone/kev-0.8b" with base_url="http://localhost:8080" works as a free local teacher.

Where shad0w loses#

  • Sentiment and tone (SST-2): the table reaches 79% accuracy at best, certifies 0% and defers everything. That is the correct behaviour, and a decision model or your LLM is the right tool.
  • Legal clauses (LEDGAR, 100 labels, long texts): 13% served in an earlier run.
  • Raw accuracy: a decision model answers every input; shad0w only answers the certified share and hands the rest back. If you need one engine for everything, use the decision model and put shad0w in front of it.
  • Cold start: nothing is served until ~1,000 answers are logged and train() has run.
