Architecture & file format#

Data flow#

 SHADOW (days, in production)        COMPILE + CERTIFY (minutes, any CPU)          SERVE (your process)
 ┌──────────────────────────┐      ┌───────────────────────────────────┐      ┌─────────────────────────────┐
 │ traffic → your model     │      │ split: fit 70% | calibration 30%  │      │ text → hashed items          │
 │      │                   │ ───► │ fit the int8 table (L-BFGS)       │ ───► │ → int8 lookup-and-add        │
 │      ▼                   │      │ Learn-then-Test vs your model     │      │ → confidence, radius, flags  │
 │ teacher_log.jsonl        │      │ bundle/: *.s0 + manifest.json     │      │ certified ? serve : defer    │
 └──────────────────────────┘      │          + certificate.json       │      │ drift guard · audits         │
                                   └───────────────────────────────────┘      └─────────────────────────────┘

The table#

For an input with item multiset I (|I| = n) and options j = 1..K:

logit_j(x) = ( s_j · Σ_{h ∈ I} T[h, j] / n  +  b_j ) / τ          p(x) = softmax(logit(x))
  • T is int8 over the retained hash buckets, quantised per option with s_j = max_h |W[h, j]| / 127.
  • b_j is a float bias and τ is a fitted temperature.
  • Items missing from the table contribute 0 but still count in n.
  • Order invariance: every option is scored independently by the same rule, so reordering options never changes a decision. (Generative decision models flipped 5.5–17% of decisions when their options were reversed.)

Hashing (no tokenizer)#

  1. Text is ASCII-lowercased byte-wise. Words are runs of [a-z0-9] or bytes ≥ 0x80, so every script passes through.
  2. Items are word unigrams (w+word), word bigrams (b+a+\x01+b) and character trigrams of ' '+word+' ' (c+tri).
  3. Each item is hashed with FNV-1a-32 and masked to 22 bits. Words over 256 bytes are truncated, and empty input yields one special item.

Training#

  • Mean-form sparse bag matrix, then multinomial logistic regression (Σ CE + ||W||²/2C) with full-batch L-BFGS.
  • C is picked from {100, 300, 1000, 3000} on a 15% hold-out.
  • Temperature is fitted on out-of-fold predictions. Long texts get IDF folded into the weights.
  • Weights are quantised to int8.

Exact robustness radius#

G[y, j] = max_h (T[h, j] − T[h, y])·scale is the most an inserted item can help option j against y. Since each insertion adds one to n, the minimum number of insertions that flips y to j is:

k_j = ⌊ (−D_j − Δb_j · n) / (G[y, j] + Δb_j) ⌋ + 1        (∞ if the denominator ≤ 0);   radius = min_j k_j

It is exact for item insertions under the hashed model, and it treats hash collisions as available to the attacker.

Bundle layout#

bundle/
  manifest.json      format, meta (mode, teacher, alpha, delta); per question: type, options, threshold,
                     alpha, r_min, drift-guard state, calibrated
  <question>.s0      one table per question
  certificate.json   statement, alpha, delta, per-question statistics, SHA-256 of the data used

.s0 table format (little-endian)#

Offset Field Type
0 magic S0RX 4 bytes
4 version (= 1) uint32
8 F, rows uint32 (1 … 2²²)
12 K, options uint32 (2 … 1024)
16 temperature float32 (> 0)
20 keys[F], strictly increasing bucket ids uint32 × F
… T[F·K], row-major int8 × F·K
… scale[K] float32 × K
… bias[K] float32 × K
… G[K·K], pairwise max gaps for the radius float32 × K·K

Size = 20 + 4F + F·K + 8K + 4K² bytes. For 77 options and 24.7k rows that is 2.0 MB, about 405 KB gzipped. All three runtimes reject a file whose magic, version, shape bounds, key order or exact size do not match.

Runtimes#

Runtime Per decision (77 options) Has
C core (inside the wheel, or any FFI) ~1 µs decision, probabilities, radius
Python (shad0w.load) 15 µs p50 / 28 µs p99 through the C core (full API overhead included); slower on the numpy fallback everything: flags, radius, drift guard, audits
JavaScript (npm i shad0wllm) 7–11 µs p50 decision, probabilities, certified threshold
HTTP (shad0w serve) 0.19 ms single client; ~11,000 req/s per process everything Python has

Security and privacy#

  • No network access and no telemetry at runtime.
  • Bundles hold hashed n-gram weights, not text. Frequent short phrases can still be guessed by brute force, so treat bundles trained on sensitive text as sensitive.
  • certificate.json stores SHA-256 hashes of the records, never the records.
