Getting started#

shad0w turns a decision your model already makes (an intent, a route, a policy check, a topic) into a small table that answers in microseconds on a CPU. It also states, as a finite-sample certificate, how often the table may disagree with your model. The table answers only what it can certify. Everything else goes to your model, as before.

Install#

pip install shad0wllm                 # runtime: numpy only, C core included in the wheel
pip install "shad0wllm[compile]"      # + compiling and certifying bundles (scipy, scikit-learn, torch)
npm i shad0wllm                       # JavaScript runtime for Node, browsers and edge workers

Python 3.10–3.13 on Linux, macOS and Windows. For a smaller install, install CPU-only torch first: pip install torch --index-url https://download.pytorch.org/whl/cpu.

Five-minute tour#

Run the bundled example. It needs no downloads and finishes in under a minute:

git clone https://github.com/2796gaurav/shad0w && cd shad0w
pip install -e ".[compile]"
python examples/quickstart.py

compiled + certified in 16.1s -> examples/out/bundle
agreement with teacher 98.0%; certified share 100.0% at alpha=5%
'someone stole my card yesterday'        lost_card  conf=0.98 certified=True  lost_card
'how much is in my account'              balance    conf=1.00 certified=True  balance
"what's the weather"                     transfer   conf=0.44 certified=False  -> defer to your model

The last line is the point. The table still guesses transfer, but it knows the guess is below its certified threshold, so the request goes to your model.

The three things you write#

1. A schema. These are the options your model chooses from. Option names must match your model's answers exactly. One-line criteria are optional.

{
  "intent": {"type": "choice", "criteria": {
    "refund": "the customer wants money back",
    "lost_card": "a card is lost or stolen",
    "balance": null
  }},
  "urgent": {"type": "yesno"}
}

2. A log of your model's answers. Use JSON Lines with one decision per line. The Shadow wrapper writes this for you.

{"text": "my card was stolen yesterday", "intent": "lost_card", "urgent": true}

3. One line in your code:

import shad0w

sh = shad0w.Shadow("bundle/", teacher=ask_my_llm, log="teacher_log.jsonl")
d = sh.decide(text)
d.answer, d.source      # ("lost_card", "table") or (<your model's answer>, "teacher")

The whole loop#

  1. Log. Run shad0w.Shadow(None, teacher=..., question="intent", log=...). Every call goes to your model and is logged.
  2. Compile and certify once you have 1,000+ answers: shad0w shadow --schema schema.json --data teacher_log.jsonl --teacher my-llm --out bundle/
  3. Read the certificate. shad0w report --bundle bundle/ shows agreement and the certified share at your α.
  4. Serve. Point Shadow at bundle/. Deferred answers keep being logged, and 1% of certified answers are spot-checked against your model.
  5. Re-certify weekly, or when traffic changes: shad0w certify --bundle bundle/ --data last_week.jsonl. Recompile from the growing log when you want more offload.

Words used in these docs#

Term Meaning
Teacher the model you already run: an LLM, a hosted decision API, an in-house classifier
Shadow log (text, teacher answer) records collected while the teacher keeps serving
Bundle a folder with one .s0 table per question, manifest.json and certificate.json
α (alpha) the certified disagreement bound, e.g. 0.05. Lower α means fewer answers served locally
δ (delta) the chance the certificate is wrong because the calibration sample was unlucky. Default 0.1
Offload the share of traffic the table answers itself
