Get started in 5 minutes#

shad0w learns the answers your LLM gives to a small, fixed-choice question (which intent, which team, spam or not) and serves the ones it is certified on from a 1.5 MB table in about 2.4 µs. Everything else still goes to your LLM.

1. Install#

pip install "shad0wllm[compile]"     # Python 3.10–3.13 · Linux, macOS, Windows

The package installs as shad0wllm, imports as shad0w, and adds a shad0w command. [compile] adds what training needs (scipy and scikit-learn). Add [torch] for faster training on large logs. Serving alone needs only pip install shad0wllm, which depends on numpy. Run shad0w doctor to check the setup.

Already using the OpenAI Decisions API, or a decision model such as Jev, Kev or Laya? You can skip the code below entirely: run shad0w proxy and move your client's base_url. See Decisions API & System One.

2. Wrap the question you already ask your LLM#

import shad0w

intent = shad0w.decision(
    "intent",
    options={
        "refund":    "the customer wants money back",
        "lost_card": "a card is lost or stolen",
        "balance":   "the customer asks about their balance",
        "other":     "anything else",
    },
    llm="openai/gpt-6-luna",          # reads OPENAI_API_KEY
)

d = intent("someone stole my card at the airport")
print(d.answer, d.source)              # lost_card teacher

Tip: always include an other option. The table can only answer with one of your options. Without a catch-all, an off-topic message ("tell me a joke") gets mapped to the closest real intent, sometimes confidently. With other, it lands there, or goes to your LLM.

On day one there is no table yet, so every call goes to your LLM. shad0w writes each (text, answer) pair to shad0w/intent/log.jsonl.

Not on OpenAI? Use anthropic/…, gemini/…, groq/…, ollama/llama3.1, a decision model (systemone/…, openai-decisions/…) or any OpenAI-compatible server. See Connect your LLM. Already have a function that returns the answer? Pass it as llm=my_function.

3. Train once ~1,000 answers are logged#

print(intent.train())        # compiles + certifies, then starts serving from the table

{'certified_share_on_calibration': 0.68, 'agreement_with_teacher': 0.84, 'threshold': 0.91, 'accepted': True, ...}   # example output

From now on:

intent("my card was stolen")
# Decision(answer='lost_card', source='table', confidence=0.99, certified=True, flag=None, latency_us=9.6)

intent("can you explain compound interest like I'm five?")
# Decision(answer='other', source='teacher', confidence=0.41, certified=False, flag='low_confidence', ...)

The second message went to your LLM because the table was not sure enough. That answer is logged too, so the next train() knows more.

4. Look at what it is doing#

shad0w try --bundle shad0w/intent/bundle "my card was stolen" "explain interest"
shad0w stats --log shad0w/intent/log.jsonl

intent.stats()      # {'table': 812, 'teacher': 388, 'offload': 0.68, 'audit_disagreement_upper': 0.041, ...}

See Monitoring for the live dashboard, Prometheus metrics and hooks.

What next#

  • Roll it out safely: shadow → canary → serve.
  • Tune it: α, spot checks, labels that must never be served: Configuration.
  • Change no code at all: run the OpenAI-compatible proxy and point your client's base_url at it.
  • Something not working: shad0w doctor, then Troubleshooting.
  • JavaScript, browsers, edge: JavaScript.
  • Any language: HTTP or C.
  • LangChain, LiteLLM, Vercel AI SDK, FastAPI: Frameworks.
  • Keep it fresh: Training & retraining.
  • What "certified" means: The guarantee.
