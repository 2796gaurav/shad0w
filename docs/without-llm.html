Running without an LLM#

shad0w learns from a teacher: whatever gives the right answer today. An LLM is the most common teacher, but it is not required. Three other set-ups work just as well:

Teacher When it fits
People (support agents, moderators, reviewers) You already label things by hand, or can label a few hundred examples
An existing classifier or rule set You want the same decisions in microseconds, in the browser, or offline
No teacher at serving time Labels exist only for training; uncertain messages go to a queue, a default, or a person

The certificate then compares the table with that teacher: people, rules or model, whatever produced the answers.

1. Collect answers#

Any JSON Lines file with a text and one field per question works:

{"text": "my card was stolen at the station", "intent": "lost_card"}
{"text": "why was I charged twice?", "intent": "refund"}

Or record them as they happen, from your own review tool:

intent = shad0w.decision("intent", options=["refund", "lost_card", "balance", "other"])   # no llm=
intent.record("my card was stolen at the station", "lost_card")    # an agent's label

Aim for about 1,000 labelled examples (100 is the hard minimum), spread over your options the way real traffic is. For labels that people produced, about 300 extra examples held out for calibration give a certificate against the truth: see shad0w calibrate in Training.

2. Train#

intent.train()                    # or: shad0w train --log shad0w/intent/log.jsonl --out shad0w/intent/bundle

3. Serve with a fallback#

Without a teacher, something must answer the messages the table is unsure about. fallback is that something:

intent = shad0w.decision("intent", fallback="needs_review")      # a fixed answer
intent("my card was stolen")         # Decision(answer='lost_card', source='table', certified=True, ...)
intent("the thing with the stuff")   # Decision(answer='needs_review', source='fallback', flag='low_confidence', ...)

A function works too: rules, a lookup, or a ticket in a human queue:

def route_to_person(text):
    queue.put(text)                  # an agent will label it; record() it later to keep learning
    return "pending"

intent = shad0w.decision("intent", fallback=route_to_person)

Fallback answers come back with source="fallback" and are never written to the training log: they are not a teacher's judgement. When a person later labels the message, call intent.record(text, label) so the next training run learns from it.

Only the certain answers#

If you only want the table's answer when it is certified, and want to decide yourself what to do otherwise, use peek:

d = intent.peek("my card was stolen")     # a Decision when the table would answer, else None
if d is None:
    ...                                   # your own path: a default, a queue, a slower model

From an existing classifier#

Any fn(text) -> label is a teacher. Wrap a slow classifier and the table takes over its common cases:

intent = shad0w.decision("intent", options=LABELS, llm=my_bert_classifier)   # a callable, not an LLM

In the browser or at the edge#

A trained table needs nothing at run time: no network, no key, no model. In JavaScript, check certified and decide what to do with the rest:

const a = bundle.decide(text).answers.intent;
const label = a.certified ? a.choice : "needs_review";

Label-free start (experimental)#

shad0w compile --unlabeled texts.txt --schema schema.json builds a first table from option names and unlabelled text with a sentence encoder (pip install "shad0wllm[logs]"). Such a table is uncalibrated: it serves nothing until real answers certify it, because a certificate computed on its own guesses would be meaningless. Use it to bootstrap, then record real labels.
