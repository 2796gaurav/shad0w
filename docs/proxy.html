The proxy: zero code changes#

shad0w proxy sits between your app and any OpenAI-compatible API. Your code keeps using its OpenAI SDK. Only the base_url changes.

1. Start it#

pip install shad0wllm
shad0w proxy --upstream https://api.openai.com/v1

shad0w proxy on http://127.0.0.1:8010/v1  ->  https://api.openai.com/v1
  dashboard http://127.0.0.1:8010/   metrics http://127.0.0.1:8010/metrics   data /home/you/app/shad0w

The upstream can be OpenAI, Groq, Together, OpenRouter, Mistral, a LiteLLM proxy, Ollama (http://localhost:11434/v1), vLLM or anything else that speaks the chat completions API.

2. Point your client at it#

from openai import OpenAI
client = OpenAI(base_url="http://localhost:8010/v1")

const client = new OpenAI({ baseURL: "http://localhost:8010/v1" });

Your API key is forwarded to the upstream as usual. To keep the key in the proxy instead, use --api-key-env OPENAI_API_KEY.

3. Mark which calls are decisions#

Pick whichever is easiest:

# a header
client.chat.completions.create(model="gpt-4o-mini", messages=msgs, extra_headers={"X-Shad0w-Question": "intent"})

# a model name: "shad0w/<question>" (the upstream model comes from --model, or "shad0w/intent@gpt-4o-mini")
client.chat.completions.create(model="shad0w/intent@gpt-4o-mini", messages=msgs)

# a structured-output schema named after the question: nothing else to change
client.chat.completions.create(model="gpt-4o-mini", messages=msgs, response_format={
    "type": "json_schema",
    "json_schema": {"name": "intent", "schema": {"type": "object",
        "properties": {"intent": {"type": "string", "enum": ["refund", "lost_card", "balance", "other"]}}}}})

The text shad0w learns from is the last user message. Put the thing to classify there and keep instructions in the system message.

Unmarked requests (chat, embeddings, image calls, streaming) are forwarded untouched.

What happens to a decision#

Situation What the proxy does
No trained table yet Forwards to the upstream, returns its reply untouched, logs the answer to shad0w/<question>/log.jsonl
Table certified for this text Answers itself in microseconds with a normal chat.completion
Table not sure Forwards, returns the reply, logs the answer (training data for next time)
Upstream error Returns the upstream's error as-is

A table answer is shaped like the request asked:

  • plain text: the option name;
  • JSON object mode: {"intent": "lost_card"};
  • your JSON schema: your field name;
  • stream: true: server-sent events.

It carries an extra shad0w field, plus the headers x-shad0w-source: table, x-shad0w-confidence and x-shad0w-latency-us.

4. Train#

shad0w stats --log shad0w/intent/log.jsonl        # ready yet?
shad0w train --dir shad0w --question intent       # the running proxy picks the new table up within a second

Or let the proxy do it: shad0w proxy --upstream ... --auto-train 1000 retrains every 1,000 new answers. Training needs pip install "shad0wllm[compile]".

Options#

Flag Default
--upstream https://api.openai.com/v1 the real API
--dir shad0w logs and tables live in <dir>/<question>/
--model upstream model for model="shad0w/<question>"
--api-key-env send this env var as the upstream key instead of the client's
--audit-rate 0.01 share of table answers re-asked upstream in the background, as live spot checks
--auto-train off retrain every N new answers
--alpha 0.05 certified disagreement bound for training
--cost-per-call your cost per LLM call, to show money saved on the dashboard
--schema a schema.json naming each question's options (otherwise taken from the request's enum or from the answers seen)
--no-text keep request text off the dashboard
--host, --port 127.0.0.1, 8010

The proxy has no authentication of its own. Keep it on localhost or inside your network.
