FAQ#

Is this a cache?#

No. A cache answers only texts it has seen. shad0w generalises to new wordings of what it learned, and its guarantee covers new texts drawn like your traffic.

How much traffic does it take over?#

On 3 public intent and topic tasks, 61–86% at α = 5% (teacher: gpt-4.1-mini (OpenAI)), with end-to-end accuracy within 1 point of the LLM alone. It grows with logged traffic: 0% at 250 answers and 60% at 10,000 on BANKING77. Sentiment-like tasks: 0%, by design. Sources: benchmarks.

How fast is it?#

1.0 µs per decision in C, 10 µs in JavaScript, and 5.2 µs in Python (2.4 µs without the per-option probabilities). Through the proxy, 0.53 ms end to end at the client; the bare HTTP hop is 0.17 ms on localhost. Measured on an Apple M5 Pro; see benchmarks.

Does it work with the OpenAI Decisions API?#

Yes, with no code change. Run shad0w proxy --upstream https://api.openai.com/v1 and set your client's base_url to it. Requests to /v1/decisions already name each question and list its answers, so the proxy needs no marking. Questions the table is certified on are answered locally in the same JSON shape; only the rest are sent to gpt-6-luna, and their answers are logged for training. See Decisions API & System One.

Jev, Kev and Laya are already fast. Why add shad0w?#

They answer in milliseconds to a second per call, from a hosted API or a model you run. The table answers its certified share in microseconds on your CPU, with no per-call price and a written bound on how often it disagrees with them. It needs about 1,000 logged answers per question first and never covers everything. Use the decision model as the teacher and let shad0w take the repeat traffic. See How it compares.

How do I tune it?#

alpha sets the bound, audit_rate the spot checks, mode and canary the rollout, never_serve the labels that always go to your LLM. Set them in code, in SHAD0W_* variables or in shad0w.toml; shad0w config shows the result. See Configuration.

Can I set the confidence threshold myself?#

You can make it stricter with min_confidence; the certificate still holds. force_threshold lets the table answer below the certified threshold, but those answers are marked certified=False with the flag manual_threshold, because the guarantee no longer covers them.

Does it need a GPU, labels or a training pipeline?#

No. It needs a CPU, your LLM's answers, and seconds of training.

Which LLMs can be the teacher?#

Any. Presets cover OpenAI, Anthropic, Gemini, Groq, Together, OpenRouter, Mistral, DeepSeek, Fireworks, xAI, Ollama, vLLM and LM Studio, plus the OpenAI Decisions API (openai-decisions/) and System One decision models such as Jev, Kev and Laya (systemone/). Anything else works through base_url=, a complete= function, or a plain fn(text) -> answer.

Does any data leave my machine?#

No. Logs, training and tables are local files. The only network traffic is the LLM calls you already make.

What happens when my LLM changes (new model, new prompt)?#

The certificate is against the old teacher. Clear or rotate the log, let the new LLM answer for a while, and retrain. Until then, keep the old table (it is certified against the old LLM) or remove it to send everything to the new one.

Off-topic messages get a real intent. Why?#

The table can only answer with one of your options. Add a catch-all such as "other": "anything else". Your LLM then labels off-topic traffic other, the table learns that, and off-topic messages stop landing in real intents.

Can I use it for multi-label or open-ended output?#

No. One answer from a fixed list per question. For several labels, use one yes/no question per label.

How big is the table?#

About 1.5 MB for 77 options. It grows with the number of options and the vocabulary of your traffic, not with the amount of traffic.

Is it safe against adversarial input?#

Use exposed=True for user-facing, adversarial channels. The table then also defers any answer that a few inserted words could flip (an exact robustness radius). For high-stakes decisions, keep your LLM in the loop.

What does it cost?#

Nothing. Apache-2.0.

Where do I report a problem or share results?#

On GitHub. Results on your own data, good or bad, are very welcome.
