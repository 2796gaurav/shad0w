Decision Bench

Six public decision tasks. shad0w and the open decision models answer the same rows, one decision at a time, on a CPU only, and every model's confidence goes through the same certifier. The decision models run zero-shot, as shipped; shad0w learns from each task's training split.

How it is measured

  1. Decision models: Julia-1, Laya and Kev-0.8B through llama.cpp (GGUF builds from ggml-org), Decider-0.8B and GLiNER2.5-Decide through their own Python packages behind the same request shape. Every one runs on the CPU only. Other small decision models found on Hugging Face (Laya-multilingual, Laya-typed-decisions, d1-omni-600M) did not load in this llama.cpp build and are not included.
  2. Same rows for everyone. Each task's test rows are a fixed random sample (seed 0) of the dataset's test split; calibration rows are a fixed sample of its train split, held out from training. The three largest decision models are not part of this run. A decision model that takes over 1 s per decision on a task (Kev-0.8B and Decider-0.8B everywhere, GLiNER2.5-Decide on CLINC150) answers the first 150 test rows and is certified on the first 150 calibration rows (marked subset); shad0w's numbers next to them in the cascade table use the same 150 rows. Decider-0.8B ran on its package's reference PyTorch kernels (the optimised ones are GPU-only), about 5 s per decision; its single-thread time was not measured.
  3. Accuracy is against the dataset's true labels, with a 95% Wilson interval.
  4. Time per decision is the wall time of one call with one input, measured from Python after 20 warm-up calls. In-process systems run on one thread. Decision models run in llama.cpp on the CPU only (--device none) with the thread count shown above, over HTTP on localhost; their single-thread time is listed separately.
  5. Certified coverage: one certifier for every system. Learn-then-Test with a Clopper–Pearson bound picks a confidence threshold on the calibration rows so that, with 90% confidence, the error among answers above it is at most 5%. Coverage is the share of test rows above it; served error is the error on them.
  6. Cascade: shad0w (its default, student="auto") answers what it certifies and the decision model answers the rest. Accuracy and mean time are for the pair on the decision model's test rows.
  7. Decision models are asked one neutral instruction with each option's short description. It was chosen on calibration rows before any test row was run (a task-specific question gave Julia-1 25% on SMS spam).

What this does not show

  • shad0w is trained on each task; the decision models are not. A decision model you fine-tune on the task would do better than its zero-shot score here.
  • Here the "teacher" is the dataset's labels. In production shad0w learns from your LLM's answers, and its certificate is against that LLM, not the truth.
  • One machine, one run. Latency depends on the CPU, the batch size (always 1 here) and HTTP for the decision models.

Check it yourself

Every answer of every system is saved in bench/results/preds/. Re-score them without running any model, or re-run everything:

# re-score the saved predictions (no model, no network)
python bench/score.py
# rebuild this page from results.json
python bench/render.py
# re-run every system (about two hours on a laptop CPU)
python bench/run.py
