System Zero: the reflex layer your LLM stack is missing

LLMs think slowly. Decision models think fast. But most of what an app asks is a repeat, and repeats need a reflex. A case for System Zero, and how shad0w implements it.

Gaurav Chauhan2026-10-084 min readsystem zeroarchitecturedecision modelsllm cost

Pull your hand off a hot stove and you will notice something odd: you moved before you felt the pain. The signal never reached the part of your brain that thinks. It went to your spinal cord and straight back out. A reflex.

Your brain is not lazy for doing that. It is efficient. The thinking parts are slow and expensive, so the body keeps them for questions that need them, and handles the familiar ones lower down, faster, and without asking.

Most software built on language models has no such layer. Every question, however familiar, goes all the way up.

Three ways to answer a question#

System 2the LLM thinks1416 ms per call
System 1a decision model picks271 ms (Kev-0.8B, local)
System 0a reflex answers what it has learned1.0 µs in C · 2.4 µs in Python

Psychologists talk about System 2 (slow, deliberate reasoning) and System 1 (fast, intuitive judgement). AI infrastructure grew the same two layers this year.

  • System 2 is the general LLM. You describe the task in a prompt and it reasons its way to an answer. It is flexible and slow: 1416 ms for a single fixed-choice decision from gpt-4.1-mini (OpenAI) in our runs.
  • System 1 is the decision model. OpenAI's Decisions API and the System One family of decision models (TypeSafe's Jev, and open models such as Kev and Laya that speak the same API) take a question and a fixed list of answers, and return a probability for each in one forward pass. That is tens to hundreds of milliseconds instead of seconds.

Both layers compute every answer from scratch. Ask either one "which intent is my card got stolen?" a million times and you pay for a million computations of the same thing.

The missing layer#

System Zero is the reflex. It does not reason and it does not compute probabilities over a prompt. It remembers how the layers above answered questions like this one, and it answers immediately, but only when it can prove the answer will match.

Four rules define it:

  1. It learns from the layer above, never from scratch. No labelling project, no new model to own. The LLM or decision model you already run is the teacher; System Zero studies its answers.
  2. It only answers what it can prove. A reflex that fires at the wrong time is worse than none. System Zero carries a written, statistical guarantee on how often it disagrees with its teacher, and passes everything else up.
  3. It lives where the request is. In your process, in a browser tab, in an edge worker. No network hop: the point of a reflex is that it does not travel.
  4. Every pass upward teaches it. Whatever it hands to the layer above comes back with an answer, which becomes training data. The share of traffic it can answer grows on its own.

Why this matters now#

Look at what production apps actually send to their models. A support bot routes messages into a few dozen intents. A moderation pipeline asks "spam or not?" An agent framework asks "which tool next?" between every step. These are not open-ended questions. They are the same few questions, asked about wording that repeats, over and over.

For that kind of traffic, a reflex does not need to be clever. A table of word and character patterns, learned from the teacher's own answers, is enough. On the three intent and topic tasks we measured with gpt-4.1-mini (OpenAI) as the teacher, such a table answered 61–86% of the traffic. That share comes back in microseconds instead of a model call, and it disagrees with your LLM on at most α = 5% of what it serves (90% confidence); realised 3.0–6.0% in our runs.

The remaining 14–39% still goes up, as it should.

What System Zero is not#

A reflex is not a replacement for thinking. It cannot:

  • write a reply;
  • read sarcasm (on SST-2 sentiment it certified 0%, so everything went up);
  • or answer a question that needs knowledge of the world.

It is also not a cache. A cache only recognises exact repeats. A reflex generalises to new wordings of a familiar question, and its guarantee covers messages it has never seen, as long as traffic resembles what it learned from.

That last condition matters. When traffic shifts, a good reflex notices and steps back. shad0w watches its own confidence and, when that drifts, sends everything up until it has relearned.

shad0w is a System Zero#

shad0w is our implementation of the idea:

  • Learns: a hashed word and character table with 8-bit weights, 1.5 MB for 77 options.
  • Proves: a Learn-then-Test certificate against the teacher.
  • Lives anywhere: runtimes in Python, JavaScript and C that give the same answers.
  • Connects: a proxy that sits in front of chat models, the OpenAI Decisions API and System One servers with no code change.

It sits below whatever you run today. Put it in front of a general LLM and it takes the repeats off System 2. Put it in front of a decision model and it takes them off System 1: with Kev-0.8B as the teacher, mean latency per decision fell from 382 ms to 115 ms, and accuracy moved +1.0 points.

The thinking layers get to do what they are good at. The reflex handles the rest.
