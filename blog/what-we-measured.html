What we measured: where shad0w wins, and where it loses

Real LLMs, real proxies, public datasets and the same certifier for every method. The numbers that make shad0w worth using, and the ones that show when not to.

Gaurav Chauhan2026-10-065 min readbenchmarksevaluationcomparisonhonesty

Benchmarks for developer tools usually measure the happy path on the author's laptop. We tried to do better:

  • real LLMs, called through the proxy exactly as an application would;
  • public datasets;
  • every competing method put through the same certifier;
  • the losses published next to the wins.

Every number below comes from a result file in the benchmark kit and is inserted into this page by the site build. None is typed by hand.

1. A real LLM, a real proxy, an unmodified client#

The set-up a user would have: the official openai SDK talks to shad0w proxy, which talks to the LLM. We logged answers, trained, and sent fresh messages the table had never seen. Then we checked agreement by asking the LLM again directly, not through the table.

run LLM p50 answered by the table (fresh traffic) agreement with the LLM on those answers logged fresh messages
gpt-4.1-mini (OpenAI) · 77 intents 1397 ms 51.3% 95.9% 4,999 1,000
gpt-4.1-mini (OpenAI) · 8 intents 1416 ms 94.3% 97.2% 1,000 300
local Ollama model · 8 intents 1960 ms 96.0% 97.6% 1,000 300
Decisions API shape (mock upstream) 174 ms 92.7% 98.2% 1,000 300

The openai SDK → shad0w proxy → the LLM, on this machine; agreement re-asks the LLM directly. Source: results/b4_*.json.

On the 77-intent run, about half of all decisions never reached the LLM. Those came back in milliseconds at the client instead of 1397 ms, and agreed with the LLM 95.9% of the time. With 8 intents, nearly everything was answered locally.

What this says:

  • An embedding classifier answers more traffic. A logistic head on bge-small certified more than the table, at a few milliseconds per decision and a model of over a hundred megabytes. If coverage is all you care about and a few milliseconds are fine, use one, and put the same certifier on it.
  • shad0w answers in microseconds, anywhere. It needs no model at run time and fits in about 1.5 MB. That buys browser and edge deployments, and decisions that cost nothing.
  • A semantic cache certifies nothing here. Nearest-neighbour answers looked plausible, but they could not prove agreement at α = 5%.

That curve is the honest version of "set and forget". On a 77-option task the table certified nothing until roughly five thousand answers had been logged. Then it climbed. A few-option task gets going far sooner. The scale page has the details.

4. Speed#

A decision costs 1.0 µs in C, 10 µs in JavaScript and 2.4 µs in Python (5.2 µs with per-option probabilities). Through the HTTP server the round trip is 0.17 ms; through the proxy, as seen by the openai SDK, 0.53 ms. Measured on an idle laptop CPU.

5. In front of a decision model#

Decision models (System One) are already fast. Put shad0w in front of one and it still pays. With Kev-0.8B as the teacher, the table answered 70% of BANKING77. Mean latency per decision fell from 382 ms to 115 ms, and accuracy moved +1.0 points.

Where it loses#

We would rather you hear these from us.

  • Tone and sentiment. On SST-2 the table certified 0% and sent everything to the LLM. That is the right behaviour and saves nothing. A word table cannot read sarcasm.
  • Cold start on many options. See the curve above. Plan on a few weeks of logging for large intent sets.
  • Traffic that shifts. On CLINC150, test traffic carried about ten times the share of off-topic messages that the training log did, and realised disagreement went over α. The drift guard flags this within a few hundred decisions in live use. The lesson is in the docs: log off-topic traffic at its real rate, and always offer an other option.
  • Inconsistent teachers. A small local model that answered the same message differently on different days capped what any student could certify. A table can only be as consistent as its teacher.

What we did not measure#

We have not run against hosted Jev, Kev-4B or pplx-decider, because we had no credits. The real OpenAI Decisions API is covered only by a local mock of its wire format. The full list, with the commands to rerun everything, is in the benchmarks page.

Run it yourself. The benchmark kit is a zip with setup and run scripts and a results template. Every figure on this site rebuilds from its output.
